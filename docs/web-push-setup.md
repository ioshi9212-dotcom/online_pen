# Web Push для Online Pen (Amvera)

## Что реализовано
- Подписка на push по кнопке для мастера (кабинет `/admin`), одобренного клиента (`/my`) и ожидающего подтверждения клиента (`/pending`). Подписка хранится в таблице PostgreSQL `PushSubscription`, а не в памяти контейнера.
- Сервис-воркер `/sw.js` показывает уведомление на устройстве и открывает соответствующий раздел сайта при нажатии.
- Мастеру: новая регистрация, новая заявка на запись, лист ожидания, отмена клиентом.
- Клиенту: одобрение аккаунта, изменение/подтверждение/отмена записи мастером, добавление ручной записи.
- Тестовое уведомление по кнопке `Отправить тест`. Не чаще одного раза в минуту с одного сохранённого устройства.
- Напоминание примерно за сутки до подтверждённой записи через `POST /api/cron/push-reminders` при **настроенном внешнем планировщике**. Пока планировщик не настроен, напоминания **автоматически не отправляются**.
- Отправка выполняется после успешной записи в PostgreSQL и не влияет на сохранение регистрации или брони, если push-провайдер недоступен.
- Входящие push-данные шифруются стандартом RFC 8291, сервер идентифицируется VAPID RFC 8292.
- Браузерный endpoint допускается только от известных push-провайдеров; хозяин подписки определяется подписанными cookie, нельзя записать произвольный clientId.

## Настройка в Amvera

1. На доверенной машине с Node.js в клоне репозитория запустить `node scripts/generate-vapid.mjs`. **Не публикуйте приватный ключ** в репозитории, чате, скриншотах или логах.
2. В панели **Amvera → OpenPen → Переменные** установить:
   - `WEB_PUSH_PUBLIC_KEY` — сгенерированный публичный ключ (не секрет).
   - `WEB_PUSH_PRIVATE_KEY` — сгенерированный приватный ключ (секрет).
   - `WEB_PUSH_SUBJECT` — `mailto:` + ваш реальный email, например `mailto:you@example.com` (пример заменить).
3. Оставить уже существующие `DATABASE_URL`, `ADMIN_SECRET`, `CLIENT_SESSION_SECRET`; они обязательны для входа.
4. Выполнить Pull из `main` и новую сборку Amvera. Текущий `amvera.yml` перед запуском выполняет `db:push` и автоматически добавит таблицу подписок в пустую/существующую PostgreSQL. **Это не миграционная стратегия для зрелого проекта**: перед последующими релизами согласовать baseline и перейти на `prisma migrate deploy`.
5. Войти в кабинет мастера, открыть `/admin`, нажать **Включить уведомления** и затем **Отправить тест**. Без подписки мастера заявки не могут приходить ему как push.
6. На iPhone (iOS 16.4+) открыть сайт в Safari, нажать **Поделиться → На экран «Домой»**, запустить Online Pen **из иконки**, войти или зарегистрироваться и нажать **Включить уведомления**. Разрешить системный запрос. Для Android/desktop можно подписываться в поддерживаемых браузерах на HTTPS.
7. Сделать тестовую регистрацию и запись, а затем проверить уведомления на телефонах мастера и клиента.

Обратите внимание: **разрешение браузера, статус HTTP-отправки и появление сообщения на экране — разные вещи**. Доставка зависит от Apple/Google/Mozilla, сети, системных настроек и режима энергосбережения; тест на живых устройствах обязателен.

### Напоминания за сутки
Для сервера нужны `PUSH_CRON_SECRET` (случайная строка не менее 32 символов, хранится только в Amvera) и внешний планировщик, выполняющий раз в час:

```bash
curl --fail -X POST 'https://YOUR_REAL_APP_DOMAIN/api/cron/push-reminders' \
  -H "Authorization: Bearer $PUSH_CRON_SECRET"
```

Не подставляйте пароль в публичные ссылки и не запускайте endpoint из браузера. Без внешнего планировщика уведомления о событиях работают, **автоматические напоминания не работают**.

### Ограничения MVP
- Отправка событий best-effort: сбой push-провайдера не откатывает сохранённые данные. На будущее — очередь/повторы доставки.
- Не меняйте VAPID-ключи после того, как клиенты подписались: старые подписки придётся включать заново.
- Подписка привязана к устройству и может продолжать действовать после выхода из сайта. На общем/чужом устройстве сначала выключите уведомления.
- Вход клиента по телефону и дате рождения недостаточно устойчив против человека, который знает оба значения; желательно перейти на SMS-код/другую двухфакторную проверку.
- Чувствительные сведения (даты рождения, телефоны, пароли) в содержимое push не включаются.
