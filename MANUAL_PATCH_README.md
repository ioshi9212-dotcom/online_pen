# Manual security patch for `online_pen`

Залить содержимое ZIP в корень репозитория `online_pen` **с заменой файлов**.

## Что внутри

- `lib/adminPassword.ts`
  - новые пароли админки сохраняются как scrypt-hash;
  - старый plaintext пароль всё ещё принимается для совместимости, пока не сменишь пароль в профиле.

- `app/admin/profile/actions.ts`
  - минимальная длина нового админ-пароля увеличена до 8 символов.

- `lib/rateLimit.ts`
  - helper для ограничения попыток входа.

- `app/admin/login/page.tsx`
  - rate limit на вход мастера;
  - после успешного входа возвращает на исходную admin-страницу, если middleware отправил на логин.

- `app/login/page.tsx`
  - сообщение для клиента при временной блокировке попыток входа.

- `app/actions.ts`
  - rate limit на клиентский вход;
  - создание клиентской записи обёрнуто в транзакцию;
  - после успешной клиентской заявки `OnlineWindow` удаляется, чтобы снизить риск двойной записи.

- `lib/timezone.ts`
  - читает `APP_TIMEZONE` из env, fallback `Asia/Vladivostok`.

- `middleware.ts`
  - версия с fallback `ADMIN_SECRET || ADMIN_PASSWORD || dev-secret`, чтобы совпадать с текущим `lib/admin.ts`.

- `.env.example`
  - пример переменных окружения.

## После заливки

1. Проверь, что на Railway/деплое есть `ADMIN_SECRET`.
2. Запусти:
   ```bash
   npm run build
   ```
3. Зайди в админку.
4. В профиле мастера смени пароль на новый, минимум 8 символов — после этого он сохранится уже как hash.
5. Проверь:
   - вход в админку;
   - клиентский вход;
   - создание заявки клиентом;
   - повторный клик на то же окно должен получать `busy`.

## Важно

Если после заливки админку кидает на логин по кругу:
- проверь, что `ADMIN_SECRET` одинаковый и не пустой;
- очисти cookie сайта в браузере;
- войди заново.
